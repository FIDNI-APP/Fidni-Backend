# Fidni backend — carte du projet

Django 5 + DRF · PostgreSQL 18 (conteneur `fidni-db` sur le serveur OVH, JSONB pour les structures de contenu) · S3 (médias) · JWT (simplejwt).
Une seule stack, un seul fichier d'env, un seul compose.

## Démarrer

```bash
docker compose up --build -d      # backend prod (base fidni-db + S3), port 127.0.0.1:8080
docker compose logs -f fidni-backend
# manage.py local (WSL, venv) : lit le même .env → même base
python manage.py migrate / createsuperuser / shell
```

## Configuration — UN seul endroit

- **`.env`** (racine backend, git-ignoré) : TOUTES les variables — Django, base, S3, SMTP Brevo, CORS. Template : `.env.example`.
- Lu par : `docker-compose.yml` (`env_file`) ET `src/config/settings/base.py` (`load_dotenv`).
- Base : `DB_HOST=fidni-db`, mot de passe dans `DB_PASSWORD` (`.env`) ; `AWS_DB_SECRET_ARN` (Secrets Manager) reste possible mais n'est pas utilisé. Credentials AWS (S3) : `~/.aws` monté en RO dans le conteneur.
- Settings : `src/config/settings/` — `base.py` (tout), `dev.py`/`prod.py` (petits overrides). `DJANGO_ENV=production` dans `.env` sélectionne prod.

## Arborescence

```
backend/
├── .env / .env.example      ← config (voir ci-dessus)
├── docker-compose.yml       ← LA stack (un seul service + ~/.aws monté)
├── Dockerfile               ← image (python:3.12-slim + nginx + gunicorn)
├── entrypoint.sh            ← migrate → seed → collectstatic → nginx → gunicorn
├── requirements.txt         ← dépendances DIRECTES uniquement (~15)
├── certs/global-bundle.pem  ← CA RDS (sslmode=verify-full)
├── nginx/                   ← reverse proxy interne au conteneur (port 80 → gunicorn 8000)
├── tests/base_tables.py     ← seeder de taxonomie (pas des tests), lancé par entrypoint, construit depuis programme.py
└── src/
    ├── config/              ← urls.py racine, wsgi.py, settings/
    └── apps/                ← 14 apps Django (voir ci-dessous)
```

## Les 14 apps — qui fait quoi

| App | Rôle | Modèles clés |

| `notebooks` | Cahiers de cours | `Notebook`, chapitres/sections |

| `classrooms` | Classes prof/élèves | `Classroom`, TD lists |

| `logging` | Logs API/erreurs en base | — |
| `notifications` | Cloche : nouveau commentaire sur un contenu avec lequel on a interagi, réponse à son commentaire (regroupées par contenu), signalement traité avec la réponse de l'admin (`kind=report`, `message`) | `Notification` |

## Conventions & pièges connus

- **Taxonomie = programme officiel** (11/10/2026) : source unique `apps/caracteristics/programme.py` (niveaux → chapitres dans l'ordre d'enseignement, capacités, hors programme, théorèmes et leur domaine `DOMAINE_THEOREME`, alias d'anciens noms et d'adresses) ; API : `rang()`, `chapitres_du_niveau()`, `annexe_d()`, `traduire_noms()`, `ecarts_base()`. Y modifier le programme, jamais `tests/base_tables.py` (qui n'ajoute que). Passage de l'ancienne taxonomie : migration `caracteristics/0003_programme_officiel` (données figées, code figé dans `programme_migration.py`, rapport dans `SystemEvent` « migration ») ; répétition sur une vraie base, tout annulé : `python manage.py programme_officiel --a-blanc` (sans option : écarts base/programme, lecture seule). « Espaces vectoriels » reste un chapitre du 2ème Bac SM.
  **« 2ème Bac PC » → « 2ème Bac PC/SVT »** (12/10/2026) : migration `caracteristics/0004_pc_svt` (renomme la ligne, même id ; titres de cahiers générés ; réversible ; jouée par `migrate` AVANT le seeder, sinon niveau en double). Adresse `2eme-bac-pc-svt` (`hubs.slug` : le « / » sépare les mots, copie front `hubApi.slugify`) ; l'ancienne redirige (`programme.ALIAS_NIVEAUX`, 301). Ancien nom accepté à l'import et par l'IA (`programme.nom_niveau_actuel`, `NOMS_NIVEAUX_ANCIENS` ; travaux IA déjà créés relus au nouveau nom). 0003 garde l'ancien nom (figée) ; `programme_officiel --a-blanc` joue aussi 0004.
- **Structures de contenu** : vivent dans `Content.json_content` (JSONB). Accès via `apps/things/content_store.py` (même API que l'ancien store MongoDB, supprimé). Idem concours.
- **Generic relations** (`Vote`/`Save`/`Complete`…) : `object_id` est un **CharField** — toujours passer des ids **string** (`[str(i) for i in ...]`), PostgreSQL refuse les comparaisons varchar/bigint (bug classique hérité de SQLite).
- **Tri « Pour toi »** (`sort=recommended`, défaut des listes côté front) : `apps/things/for_you.py` — score par élève (chapitres travaillés, nouveautés, à retravailler, réussis en dernier, variété), calculé en Python puis paginé dans `ContentViewSet.list`. Vérifié par `tests/checks/check_for_you.py`.
- **Ma progression = tableau de bord** (refonte du 13/10/2026, « trop dur, plein d'infos ») : `GET /api/stats/tableau/?jours=7|30|90|0` (`apps/users/tableau.py`) — tuiles (questions réussies / en partie / à revoir, note moyenne aux EXAMENS /20, temps, jours actifs, avec la période d'avant), jours (par semaine au-delà de 120 j), notes d'examens dans le temps (barème × auto-évaluations dès la moitié corrigée, nouvelle copie au-delà de 3 jours), chapitres du programme (note aux examens par chapitre = SES questions : moyenne, min, max, série ; questions ; temps), temps chapitre › contenu › jours (partagé entre chapitres), **points faibles par théorème** (questions ratées sur la période, questions encore à refaire avec leur libellé) ; `GET /api/stats/tableau/jour/?date=` = ce jour-là. Front : `pages/progression/Progression.tsx` + `components/progression/` (graphiques SVG maison, couleurs validées). L'objectif et les états de maîtrise ne sont plus sur cette page (restent pour l'accueil « Où j'en suis », le plan de DS, les quiz). Vérifié par `tests/checks/check_tableau.py`.
- **Fenêtre « Nouveautés » à la connexion** (14/10/2026) : `apps/users/nouveautes.py` — registre `NOUVEAUTES` (id → `inscrits_avant`, `jusqu_au`, `profs`) ; `a_voir(user)` = pas encore vues, encore d'actualité, compte inscrit AVANT la nouveauté, pas prof (sauf `profs: True`) ; voyage dans le champ `nouveautes` de `UserSerializer` pour son titulaire (réponse de connexion, `GET /api/auth/user/`) ; `POST /api/nouveautes/<id>/vue/` la marque vue (`UserProfile.nouveautes_vues` {id: date}, une fois par compte, tous appareils). Contenu côté front (`components/nouveautes/registre.ts`, même id : étapes animées avec les vrais composants). Fenêtres : `progression-2026-10` (tableau de bord « Ma progression », élèves et équipe) puis `mode-sombre-2026-10` (15/10/2026, tout le monde ; bouton « Passer en mode sombre »). Mesures : actions génériques `nouveautes-vue/finie/cta/passee` + filtre par fenêtre `nouveautes:<id>:<geste>` → Pilotage › Usage, bloc `nouveautes` (`_nouveautes` : comptes réels qui l'ont vue + gestes de la période). - **Maîtrise (calculs gardés pour l'accueil, l'objectif et le plan de DS)** (13/10/2026 ; `GET /api/stats/progression/`) : trois blocs visibles sans défiler — **Ton prochain objectif** (`apps/users/objectif.py` : une priorité expliquée, ≤ 5 exercices via `devoirs._for_you(difficulties, exclude_seen, only_ids, soon_ids…)`), **Ma progression** (maîtrise estimée, évolution 30 j AVEC sa portée, chapitres évalués ; « comment c'est calculé »), **Mes chapitres** (« Pourquoi ce statut ? » = `criteres`). Calculs : `apps/users/maitrise.py` (cache 10 min `maitrise:v1:<user>`, `forget()` après évaluation, « Réussi », quiz, DS), seuils provisoires dans `maitrise_seuils.py`. États : non évalué (< 4 questions) › n'a pas tenu à la vérification (à consolider) › < 40 % durablement (à renforcer ; récents ≥ 60 % → en bonne voie « en progrès ») › tous les critères (maîtrisé : 6 questions ≥ 80 %, 2 exercices, 2 difficultés, synthèse, théorèmes, revérifié SANS aide sur d'autres questions ≥ 3 jours après, autonomie) › ≥ 60 % ou en hausse (en bonne voie) › sinon à consolider. **Journal** : `AssessmentEvent` (chaque changement d'auto-évaluation, `aide` : None = inconnue (reprise de l'existant, migration `interactions/0024`), '' = sans aide, indice, solution) et `QuestionHelp` (`POST /api/contents/<id>/aide/` {path, kind}, `*` = toutes les solutions), écrits seulement par `apps/interactions/journal.py` (vues `assess_*`). Une aide inconnue n'est jamais « sans aide ». Accueil : bloc « Où j'en suis » (`GET /api/stats/apercu/`, léger, même cache). Avis « Ce diagnostic te semble juste ? » : `UsageDaily` filtre `prog:avis:<état|objectif-type>:<oui|non>` → Pilotage › Usage (`avis_diagnostics`), pour ajuster les seuils. `validate_solution` ne crée plus de ligne sans statut (404) ; les lecteurs excluent `status=''`. Vérifié par `tests/checks/check_maitrise.py`. L'ancien `/api/stats/me/` (`my_stats.py`) reste.

## Infra

- **Serveur OVH**, 4 conteneurs Docker : `fidni-backend` (127.0.0.1:8080), `fidni-frontend` (127.0.0.1:3001),
  `fidni-tunnel` (cloudflared → ces deux ports), `fidni-db` (PostgreSQL 18, port 5432 non publié, joignable par le
  réseau Docker). Rien n'est exposé publiquement hors du tunnel.
- **Sauvegarde de la base** (avant une migration de données, par exemple) :
  `docker exec fidni-db sh -c 'pg_dump -U "$POSTGRES_USER" -Fc "$POSTGRES_DB"' > ~/fidni-$(date +%F).dump`.
  Restauration : `docker stop fidni-backend` puis
  `docker exec -i fidni-db sh -c 'pg_restore -U "$POSTGRES_USER" -d "$POSTGRES_DB" --clean --if-exists' < ~/fidni-AAAA-MM-JJ.dump`.
